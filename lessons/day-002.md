## 4. Explanation

### 4.1 Why binary?
From Day 1: hardware is physical. Deep down, a computer is made of billions of tiny switches
(transistors) that are either **ON** or **OFF** — two states. It's cheap and reliable to tell "is
there voltage or not?" but hard to reliably distinguish ten different voltage levels. So computers
count using only **two symbols: 0 and 1**. That's **binary** (base-2). Everything — numbers, text,
images, your Day 1 variable `x = 5` — is ultimately patterns of 0s and 1s in those switches.

### 4.2 Bits and bytes
- A **bit** = one binary digit: `0` or `1`. One switch.
- A **byte** = **8 bits** grouped together, e.g. `01000001`.
- With 8 bits you get 2⁸ = **256** different patterns, so one byte can represent the numbers
  **0 to 255**. (We'll see *why* 256 and not 255 patterns below.)

### 4.3 Place value — decimal vs binary
You already know decimal (base-10) place value. The number `305` means:
```
 3    0    5
10²  10¹  10⁰    →  3×100 + 0×10 + 5×1  = 305
```
Binary works the same way but with **powers of 2** instead of 10:
```
 1    0    1    1
 2³   2²   2¹   2⁰   →  1×8 + 0×4 + 1×2 + 1×1 = 11
```
So binary `1011` = decimal `11`. The powers of 2 to memorize (right to left):
`1, 2, 4, 8, 16, 32, 64, 128, ...`

### 4.4 Binary → decimal (the easy direction)
Add up the place values where there's a `1`. Example `1101`:
```
1101  =  8 + 4 + 0 + 1  =  13
         2³  2²      2⁰
```

### 4.5 Decimal → binary (repeated division by 2)
Repeatedly divide by 2, write down the **remainders**, then read them **bottom to top**. Example:
decimal `13`:
```
13 ÷ 2 = 6  remainder 1   ↑ read
 6 ÷ 2 = 3  remainder 0   │ upward
 3 ÷ 2 = 1  remainder 1   │
 1 ÷ 2 = 0  remainder 1   │
→ bottom-to-top: 1101
```
Check: `1101` = 13. ✅ (There's also a "subtract the biggest power of 2" method — try discovering
it yourself later.)

### 4.6 Why one byte = 0 to 255, not 1 to 256
8 bits have 2⁸ = 256 *patterns*. One of them (`00000000`) represents **zero**. So the range is
`0, 1, 2, … 255` — that's 256 values, but the **largest** is 255. Off-by-one traps like this are
everywhere in computing; notice it now.

## 5. Concrete examples
- `0` → `0`, `1` → `1`, `2` → `10`, `3` → `11`, `4` → `100`, `5` → `101`.
- The number `5` you used on Day 1 (`2 + 3`) is stored in RAM as the bit pattern `101`.
- `255` → `11111111` (all eight bits on). Add 1 more and you need a 9th bit.
