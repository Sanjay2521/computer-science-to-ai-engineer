## Quiz answers

**Q1 — What is a program?**
My answer: a set of instructions which the computer executes, which expects input and gives output.
✅ Correct. (Nuance: not *every* program needs input — e.g. `print("hi")` takes none.)

**Q2 — RAM vs storage (one difference + one consequence)?**
My answer: RAM is fast and won't save the data; SSD/storage is slow but can store the memory.
Example: editing a Word doc — if I save, it goes to storage; if not, it stays in RAM.
✅ Correct.

**Q3 — Put in execution-chain order.**
My answer: source code → Python interpreter → OS → CPU → output.
✅ Correct.

**Q4 — Closing the session deletes variables? Why?**
My answer: yes — the variable was living in **RAM**, and RAM is wiped when the session/power ends,
so it's lost.
✅ Correct.

**Q5 — Was the bug hardware or software? Name the error type.**
My first guess: software, interpreter issue — "syntax issue."
Corrected after running it: it was a **`NameError`**, not a SyntaxError.
- `prnt(...)` is valid *syntax*, so Python starts running it.
- It fails when the interpreter tries to **look up the name `prnt`** and finds nothing (only
  `print` exists) → `NameError`.
- A true `SyntaxError` is when the code is malformed *before* it can run (e.g. a missing `)`).

## Exercise notes

**day01_hello.py — why `"2" + "3"` ≠ `2 + 3`:**
`2 + 3` are **int** values, so `+` does arithmetic → `5`.
`"2" + "3"` are **str** values, so `+` **joins** the characters (concatenation) → `"23"`.
Same `+` symbol, different behavior depending on the **type**.

**day01_bug.py:** fixed `prnt` → `print` by reading the traceback's last line (the word before
`Error` = the error type).

## Teach-back (my own words)
We have a `.py` file. When I click Run / execute it, it goes to the **interpreter**, which reads my
code and translates it, step by step, into the low-level operations the **CPU** can carry out; the
CPU executes those as instructions, and the **terminal shows the output**.

Corrections to remember:
- The interpreter does **not** build a standalone `.exe` — it translates to low-level operations
  on the fly ("executable code" was the wrong phrasing).
- Full chain also includes the **OS** (between interpreter and hardware — manages memory/screen)
  and the **hardware** itself (electrons move, pixels light up). I tended to skip these two.
